# OpenCode local adapter: Paperclip run-scoped MCP

Problem: Paperclip heartbeat builds a run-scoped assigned-tools gateway via `buildPaperclipRuntimeMcpServers` and passes a read-only `ctx.runtimeMcp` into `adapter.execute`. The `opencode_local` adapter uses `ctx.runtimeTools` for discovery (`connections_search`, `connection_request`) but does not consume `ctx.runtimeMcp`, so assigned KB article tools are missing from OpenCode's tool list. This is independent of installation on a laptop vs K3s; reachability remains an additional runtime precondition.

Goal: Deliver the exact MCP servers provided for this run to OpenCode's temporary runtime configuration, with remote MCP URL and Bearer header, keeping existing MCP entries except run-owned name collisions. Do not create persistent agent configuration or bypass Paperclip access policy. No static KB connection or token.

Scope: `packages/adapters/opencode-local/src/server/execute.ts`, `runtime-config.ts`, their tests and narrowly relevant adapter docs. Pass `ctx.runtimeMcp?.getServers()` as a typed input to runtime config. Every server uses OpenCode `mcp.<name> = {type:'remote',url,enabled:true,oauth:false,headers:{Authorization:'Bearer ...'}}`. Do not leak credentials to logs, prompts, source control or workspace. Do not write the generated config in the project working directory. Preserve existing config and provider handling. `dangerouslySkipPermissions:false` must not suppress run MCP delivery; when there are no servers retain existing opt-out behavior. The temporary config must be cleaned after the run, including error paths. Remote target staging must receive the config if supported, with sensitive remote cleanup and reachable URL verified or a clear failure rather than implied success.

Acceptance: red-green tests prove assigned tools config, preservation and collision policy, no MCP server/permission-opt-out cases, cleanup and at least a narrow execution handoff test where practical. Run adapter tests and typecheck. Build the existing image from the accepted commit and roll out to fresh, nonproduction K3s Paperclip only after local verification; preserve one writer, old data rollback until first-use/login/secret/agent proof. End-to-end proof is a bounded agent run that lists an assigned KB article tool and reads one harmless article, without exposing credentials. Distinguish code acceptance from deployment and end-to-end verification.
